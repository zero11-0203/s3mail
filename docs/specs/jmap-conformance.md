# JMAP conformance matrix

[Documentation index](../README.md) · [JMAP](jmap.md#core-capabilities-to-implement) · [Security](security.md#scopes)

**Status:** lists what `go/internal/jmap` implements now. Requirements stay in [JMAP](jmap.md), [storage and sync](storage-sync.md) and [security](security.md). Update this matrix in the same change as any method, limit or scope. Tests are in `go/internal/jmap/jmap_test.go` unless named otherwise.

## Advertised session

| Item | Value |
| --- | --- |
| Capabilities | `urn:ietf:params:jmap:core`, `urn:ietf:params:jmap:mail`, and `urn:ietf:params:jmap:submission` when sending is configured (`SEND_ALIASES`). No WebSocket or custom capability yet |
| Submission limits | `maxDelayedSend` 0; `submissionExtensions` empty; 100 envelope recipients; 20 MiB message |
| Core limits | `maxSizeUpload` 4,194,304; `maxConcurrentUpload` 4; `maxSizeRequest` 1,048,576; `maxConcurrentRequests` 4; `maxCallsInRequest` 16; `maxObjectsInGet` 64; `maxObjectsInSet` 16 |
| Mail limits | `maxMailboxesPerEmail` 8; `maxMailboxDepth` 10; `maxSizeMailboxName` 255 UTF-8 octets; `maxSizeAttachmentsPerEmail` 20 MiB; `mayCreateTopLevelMailbox` true |
| Account id | `A` + base32 of a hash of the internal account and restore epoch: a restored account gets a new id (RFC 8620 §1.6.2) |
| State tokens | `<epoch>-<seq>`, where `seq` is the last commit that changed the type (STATE `emailState`, `mailboxState`, `threadState`, `identityState`, `submissionState`, and `deliveryState` for the push-only `EmailDelivery` type, which advances only when a commit adds an Email by delivery, import or creation); `/changes` pages end at commit boundaries; a foreign epoch or future sequence is `cannotCalculateChanges` |
| `ifInState` | Holds for every commit of a `/set` or `Email/import` call, apart from the call's own commits ([set semantics](storage-sync.md#dynamodb-storage-and-consistency-contract)): a change to the type before the first commit is the method-level `stateMismatch`; after some objects were applied, each remaining object is refused with a per-object `stateMismatch` (`TestIfInState*`, `TestMailboxIfInStateHoldsUntilTheFirstCommit` in `guard_test.go`) |
| Query states | `q<epoch>-<seq>-<hash>`, where the hash covers the normalized filter, sort and query options; another query's state is `cannotCalculateChanges` |
| `uploadUrl` | `POST /upload/{accountId}`; see [blobs](#blobs-and-push) |

## Blobs and push

| Route | Behavior | Test |
| --- | --- | --- |
| `GET /download/{accountId}/{blobId}/{name}` | Raw message (`G…`) or part (`P…-<path>`) of a live Email, or an unexpired upload (`U…`) or part of an uploaded message (`V…-<path>`), in the caller's account; a path such as `2.1` descends into attached messages; anything else 404. Always `attachment` disposition with an RFC 8187 filename, `nosniff`, `Content-Security-Policy: sandbox`, `no-store` | `TestDownload` |
| `GET /eventsource` (RFC 8620 §7.3) | `types` (`*` or Email, Mailbox, Thread, Identity, EmailSubmission, EmailDelivery); `closeafter=no` sends the current state at once, `closeafter=state` sends no initial event and closes after its first state event; `ping` up to 300 s, timed from the previous event on the 3 s poll tick; polls STATE every 3 s; comment keepalive after 60 s quiet; ends at token expiry, 14 min 30 s, or 15 s before the Lambda deadline | `TestEventSource`, `TestEventSourceEmailDelivery` |
| `POST /upload/{accountId}` (RFC 8620 §6.1) | `mail.write`; at most `maxSizeUpload` (413 `limit` problem); the body reaches Lambda base64-encoded (`binary_media_types` `*/*`); stored in the disposable blob bucket with a BLOB record; usable for 24 hours, then 404/`blobNotFound` | `TestUploadImportParseAndDownload`, `TestUploadLimitsAndScope` |

Push connection leases ([JMAP push](jmap.md#push)) are not implemented; the push function's reserved concurrency (4) caps open streams instead.
