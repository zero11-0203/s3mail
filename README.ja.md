# s3mail

[English](README.md) · 日本語

**S**3 **S**ES **S**erverless mail：AWS 上で動く、セルフホスト型・単一オーナー向けのメールシステムです。Go 製の [JMAP](https://jmap.io/) バックエンドと、オプションの AI メールエージェントを備えています。

この README 以外のドキュメントは英語です。

## 概要

s3mail を使うと、メールサーバーを運用せずに、独自ドメインのメールを 1 人のオーナーが送受信できます。複数のアドレスを 1 つのアカウントと 1 つの統合受信箱で扱えます。転送・保存・計算は AWS のマネージドサービスが担い、Go のサービスが標準の JMAP プロトコルを話すので、既存のクライアントから接続できます。

- **受信：** Amazon SES が宣言済みエイリアス宛てのメールを受け付け、元のメッセージを S3 に保存します。
- **保存：** 元のメッセージはバージョニングされた S3 バケットに永続的に保管され、メールボックスのメタデータと同期状態は DynamoDB が保持します。
- **提供：** API Gateway の背後にある Go の Lambda が、プッシュと blob ストリーミングを含む JMAP Core・Mail・Submission を実装しています。
- **送信：** 差し替え可能な SMTP リレー（最初は SMTP2GO）が、送信上限とバウンス処理付きで送信メールを配送します。SES は受信専用です。
- **検索：** S3 上の SQLite FTS5 インデックスのスナップショットを使い、元データから再構築できます。オプションでセマンティック検索も使えます。
- **サインイン：** Cognito の OAuth を使います。ターミナル用ヘルパー `mail-auth` が、有効期限の短いトークンをメールクライアントに渡します。
- **クライアント：** 動作確認済みのクライアントは [aerc](https://aerc-mail.org/) です。ブラウザ用 Web メールはオプションで、別途デプロイします。

**SES ではなくリレーで送信する理由：** 新しい AWS アカウントの SES は[サンドボックス](https://docs.aws.amazon.com/ja_jp/ses/latest/dg/request-production-access.html)から始まり、検証済みのアドレスとドメインにしか送信できず、送信数も 24 時間あたり 200 通までに制限されます。任意の宛先に送るには AWS に本番アクセスを申請する必要があり、手動で審査されるため承認されるとは限りません。外部のリレーを使えばこの審査を経ずに送信でき、リレーは差し替え可能なので、あとから別のリレーを追加することもできます。

### メールエージェント

s3mail には、メールボックス用のオプションの AI アシスタントが付属しています。Amazon Bedrock AgentCore 上の [LangGraph](https://langchain-ai.github.io/langgraph/) グラフとして構築されています。

- **質問：** コマンドラインからメールについての質問に答え、読んだメールを引用元として示します。
- **トリアージ：** 新着メールをカテゴリーと優先度で分類し、返信が必要なものに印を付け、毎日のダイジェストにまとめます。
- **下書き：** 返信の下書きを Drafts メールボックスに作成します。編集して送信するのはあなたです。
- **承認付きの操作：** 移動、アーカイブ、確認済みの下書きの送信を提案し、それぞれあなたが承認した後にだけ実行します。

```sh
agent ask "今月の請求関係のメールには何と書いてあった？"
agent draft <email id> "承諾して、代わりに木曜日を提案して。"
agent act "先週のニュースレターをアーカイブして。"   # 承認 ID を表示
agent approve <approval id>
```

エージェントは、ほかのクライアントと同じ 1 つの JMAP クライアントにすぎません。専用の OAuth クライアントとスコープを持ち、メールの保存先への AWS アクセス権は持ちません。エージェントがなくてもメールはそのまま使えます。有効にすると、メールの抜粋を外部のモデル API（OpenRouter）に送信します。詳しくは[エージェント仕様](docs/specs/agent.md)と [`agent/`](agent/README.md) を参照してください。

## 制限事項

- **JMAP のみ：** IMAP にも、ほかのクライアント向けの SMTP サブミッションにも対応していないため、JMAP クライアントが必要です。
- **1 デプロイにつき 1 ユーザー**、かつ 1 つの AWS アカウントとリージョンにつき 1 デプロイです。リソース名が固定されているためです。
- **AWS 固有のセットアップ：** DNS は s3mail が作成する新しい Route 53 ゾーンでホストする必要があります。また s3mail は独自の SES 受信ルールセットを有効にするため、そのリージョンで有効なルールセットがあれば置き換えられます。
- **リレー**は現在 SMTP2GO しか設定できません。
- **`mail-auth` は macOS 専用：** サインイン用ヘルパーはセッションを macOS のキーチェーンに保存します。
- **元のメッセージは削除できません。** これは設計上の仕様で、クライアントでメールを削除しても非表示になるだけです。
- **バックアップなし：** DynamoDB はポイントインタイムリカバリなしでメールボックスのメタデータを保持します。これを失うとフラグやフォルダーは失われますが、元のメッセージは残ります。

## はじめに

1. [費用](docs/guides/costs.md)を確認してください。個人利用の量なら月額約 2〜4 ドルに、ドメインとリレーの費用が加わります。
2. [デプロイガイド](docs/guides/deploy.md)に従って、自分の AWS アカウントにデプロイします。
3. [利用ガイド](docs/guides/usage.md)を見て、サインイン、aerc の設定、送信上限への対応を行います。

## 開発

Go（バージョンは `go/go.mod` を参照）、Terraform 1.16.6、[golangci-lint](https://golangci-lint.run/)、[gitleaks](https://github.com/gitleaks/gitleaks)、[uv](https://docs.astral.sh/uv/) が必要です。チェックは AWS アカウントなしでオフラインで実行できます。

```sh
make check    # gofmt、go vet、golangci-lint、go test -race、govulncheck、エージェントのテスト、
              # terraform fmt/validate/test、gitleaks
make build    # go/build/ に linux/arm64 の Lambda zip を作成
```

| パス | 内容 |
| --- | --- |
| `go/` | Lambda ハンドラーと、`mail-auth`・`mail-admin`・`agent` の CLI |
| `infra/` | Terraform のルート（`bootstrap`、`main`、`webmail`、`agent`）と、`terraform test` のケースを含むモジュール |
| `agent/` | オプションの Python 製メールエージェントと、そのテストおよび評価セット |
| `webmail/` | オプションのブラウザ用 Web メールのバージョン固定と Dockerfile |
| `docs/` | アーキテクチャ、ガイド、トピック別仕様、運用ドキュメント |

## 設計目標

- 実際のクライアントで動く標準どおりの JMAP の振る舞い。特定クライアント向けの近道は設けません。
- 個人利用の量に見合う、サーバーレスで低コストな運用。インフラはすべて Terraform で管理します。
- すべてのロールで最小権限の IAM。CI はメールを読めません。
- 非同期の各ステップをまたいで、耐久性があり復旧できる処理。リレーが受け付けたか不明な送信を自動で再送することはありません。
- メールをメールボックスから削除しても、元のメッセージは決して削除しません。
